# 为什么有效：上下文类绕过的底层原理

[English](mechanism.md)

本文按公开文献的口径解释**为什么**上下文类绕过会生效。本文刻意不包含任何生成有害内容的操作步骤。

## 1. 安全对齐到底是什么

模型的拒绝行为不是一个外挂模块，而是从偏好数据和红队数据里学出来的一条策略，和生成其它内容用的是同一套权重。这带来两个结果。

- 拒绝是一个**分布性质**：模型只在训练数据里出现过的那类情形下学会了拒绝。
- 拒绝**受输入形状影响**：换掉输入的形状，学到的策略就可能不触发，哪怕语义内容没变。

关于"拒绝方向"的研究认为，这个行为由一个维度相对较低的特征介导，可以被引导；关于"浅层安全对齐"的研究认为，拒绝行为高度依赖回复开头的少数几个 token。两者指向同一件事：**安全是一条学出来的响应模式，不是系统的已验证属性。**

## 2. 训练分布的问题

在多数安全训练数据里，有害意图出现在**最后一条用户消息**。于是模型学到的判别器大致是：

> 当前这条用户消息，是不是在要一个不被允许的东西？

而不是：

> 这整个会话在干什么？

任何把意图从"最后一条用户消息"里挪走的手法——挪进更早的轮次、挪进 `assistant` 轮、挪进工具结果、挪进文件、挪进摘要——打的都是这个错位。

## 3. 四个杠杆

| 杠杆 | 利用的是什么 |
|---|---|
| **上下文形状** | 长而连贯、看起来无害的前缀会改变条件分布 |
| **来源混淆** | `assistant` 轮或工具结果里的内容，被当成既定事实，而不是待评估的主张 |
| **任务重构** | "接着写""翻译一下""总结一下""把代码写出来"改变了模型以为自己正在做的事 |
| **评估边界** | 单轮分类器看到每条消息都无害；会话级意图从来没有被打分 |

## 4. 为什么多轮会侵蚀安全

文献里反复出现四种解释，它们互补而不是互相竞争。

1. **自一致性压力。** 模型一旦部分配合过，后面再拒绝就与自己的前几轮矛盾。
2. **分布偏移。** 一段很长、彼此配合的对话，离训练里的拒绝样本很远。
3. **局部判断。** 每一轮单独看都成立，而每一轮单独看都无害。
4. **前提接受。** 前面的轮次被当作可以接着往下用的上下文，而不是需要核实的主张。

实际后果：安全随对话长度衰减，而且衰减得足够平缓，以至于没有任何一轮看起来是"出事的那一刻"。

## 5. 为什么"换模型"是独立的一招

上面讲的多数是单个模型内部的事。换模型增加了一个不同的失效。

**来源不在 token 流里。** 当模型 B 收到一段由模型 A 写成的记录，这段记录里没有任何东西说明这一点。B 分不清：

- "这是我写的"
- "这是我的另一个实例写的"
- "这是另一个模型写的"
- "这是一个没有安全训练的模型写的"

于是 B 对一段自己没写过的上下文执行安全策略，隐含前提是"这是我之前的工作"。**这个前提就是漏洞。**

这也是为什么**产品**比模型更关键：跨模型拼接上下文的是产品，而没有给上下文打标的也是产品。

## 6. 为什么常规防御抓不到

| 防御 | 为什么失效 |
|---|---|
| 单轮输入分类器 | 每条消息单独看都无害 |
| 输出分类器 | 输出是合理的续写，不是可识别的载荷 |
| 逐模型红队测试 | 每个模型单独看都正常 |
| 系统提示词 | 要跟一段冗长、连贯、以 assistant 口吻写成的上下文竞争 |
| 换模型 | 换模型正是机制本身，不是缓解手段 |

## 7. 什么才真正有用

按层拆开的完整讨论见 [defense.zh-CN.md](defense.zh-CN.md)。

1. **来源标注**——给每条消息标上作者模型和信任等级，并在每次交接中保留。
2. **会话级评估**——评估累积的对话，而不只是最新一轮。
3. **边界策略**——在交接时，要么重新评估继承的上下文，要么直接丢弃。
4. **深度监控**——把长而配合、任务形状的上下文当作更高风险。
5. **签名历史**——让"谁说了什么"可防篡改。
